> **Status: implemented in 2.0.0.** The plan below is the design as approved. What
> shipped differs in these places, each found by checking the engine's source or
> by running the module's output through the in-process preflight:
>
> - `Add-VellumPdfHeading -LinkUri` was dropped: the heading renderer never reads
>   a link, so the parameter would have done nothing.
> - Image `-DecodeToRaster` works for JBIG2 only; the engine refuses JPEG 2000 and
>   CCITT Group 4 ("not yet supported").
> - Page documents were first untagged; a follow-up added tagging (`-Tagged`, PdfA2a, PdfUA1)
>   for text, shapes, images and barcodes. Links and form fields remain untagged. Form fields are refused under
>   PDF/A because their appearance uses non-embedded fonts; the in-process
>   preflight cannot see that, so the claim rests on the file contents.
> - PDF/UA-1 also needs a document title and embedded fonts; the PDF/A barcode
>   caption rule and CMYK output-intent rule were confirmed with the preflight.
> - Signing tests use in-process doubles (a timestamp authority that builds a real
>   RFC 3161 token, a revocation source, an external signer) so no network is needed.
>   A self-signed chain has no issuer, so B-LT fetches no revocation data in tests.
> - `docs/PSVellumPDF/*.md` still has to be regenerated with `./build.ps1 Docs`
>   (PlatyPS is only on the PowerShell Gallery).
> - `System.Security.Cryptography.Pkcs` floats (`10.0.*`) and the NuGet lock file / locked-mode
>   restore were removed at the maintainer's request, trading the supply-chain drift guard for
>   always restoring the newest Pkcs. It is build-time only; PowerShell's own copy runs.
> - A post-release review added the planned `Arc` shape and ICC colour for page documents, the
>   CI PowerShell bump to 7.6.9, and fixed ten findings (pie chart options, spacing for custom
>   elements, zero-page text, ignored options, revocation client, duplicated helpers).
> - veraPDF CI steps for the new samples run only in CI; locally the samples were
>   checked with `qpdf` and the in-process preflight.

# PSVellumPDF 2.0.0: bring the module up to VellumPdf 2.3.3 (Layout first, then Kernel, Barcodes, Signing, Conformance, Reader)

## Context

PSVellumPDF `main` is at **1.3.1**, pinned to **VellumPdf 1.5.4**. `dependencies/Dependencies.csproj`
references `VellumPdf.Layout` and `VellumPdf.Signing`; Kernel comes in transitively. VellumPdf `main`
is at **2.3.3**.

How this was checked: I downloaded the 1.5.4 and 2.3.3 nupkgs from nuget.org and diffed their
public surface with a metadata dump (`tools/Get-VellumPdfApiSurface.py`, committed alongside this plan). I read the 2.3.3 sources and
the CHANGELOG from 1.5.5 to 2.3.3, and diffed `src/VellumPdf.Kernel` from `v1.5.4` to `v2.3.3`.

**Compiled public API changes**

| Package | Removed | Added | Notes |
|---|---|---|---|
| Kernel | 2 | 86 | The removals are both `CcittImageLoader.Load` overloads. |
| Layout | 0 | 70 | |
| Signing | 0 | 40 | |

The 2.x cost is mostly in **behaviour**, not in signatures.

**Packaging**
- All assemblies are strong-named (token `b2757187a6d18ae5`, AssemblyVersion `2.0.0.0`).
- Signing now references **VellumPdf.Reader** and System.Security.Cryptography.Pkcs **10.0.12**. PowerShell 7.6.2 ships Pkcs 10.0.6; both carry assembly version 10.0.0.0.

**Output changes from the Kernel and Layout fixes (no wrapper code change needed)**
- **Text and fonts**
  - WinAnsi encoding for base-14 fonts, with rebuilt width tables, so text reflows.
  - Base-14 font dictionaries are shared.
- **Encryption**
  - `/P` reserved bits are now always set.
  - `EncryptMetadata = $false` is now honoured.
- **Tagging**
  - Links get `/F 4`.
  - `/StructTreeRoot` is always written when the document is tagged.
  - `/Tabs /S` is written under PDF/UA.
  - Table cells get `/RowSpan` and `/ColSpan`.
- **Metadata**: XMP now carries `pdf:Keywords`.
- **Tables (2.3.2)**: the margin is no longer applied twice, and the column count comes from the widest row.
- **Bands (2.3.2)**: header and footer text is truncated at a word boundary, and the band colour is honoured.

**New refusals**
- At `Encrypt()`: an empty owner password beside a user password.
- At save:
  - Form text that can't be encoded.
  - A non-finite form or element number.
  - A second save of the same document.
- PDF/UA-1 together with encryption is now *allowed*, but only with the `Extract` permission.

**New features**
- Layout: `PieChart`, `Add(IRenderer)`, `BandTruncations`, `TextEncodingWarnings`, async save.
- Kernel: `Linearize`, link annotation flags, `ShowTextAligned`, `AppendArc`, `GifEncoder`, `CcittOptions`.
- Signing: PAdES B-LT and B-LTA, revocation clients, `SignaturePage`, external signers and keys.
- New packages: Barcodes, Conformance, Reader.

**Features the module never wrapped, though some already existed in 1.5.4:** AcroForms, internal
links, outline `IsExpanded`, page `Rotate`, ICC colour spaces, gradients, alpha, CMYK fill, clipping,
dashes, `ImageLoadOptions`, `DocumentId`, and `Timestamp`.

`Layout.Document` keeps its `PdfDocument` private (`VellumPdf.Layout/Document.cs:39`).
`DrawContext` keeps the page and document private (`Layout/Core/DrawContext.cs:50-51`). From
Layout, only the **canvas** is reachable, and only through `Add(IRenderer)`.

## Phase 0: engine bump, interop shim, loading

1. **Dependencies.** In `dependencies/Dependencies.csproj`, set `VellumPdf.Layout`, `.Signing`,
   `.Barcodes`, `.Conformance`, `.Reader` and `.Fonts.Standard14` to `2.3.3`. Fonts.Standard14
   provides embeddable base-14 substitutes for PDF/A in the Kernel pipeline, through
   `EmbedStandard14Font(PdfDocument, Standard14)`.
   Then regenerate `packages.lock.json` with the command documented in the csproj. Ask before closing #56 as superseded.
2. **Interop shim.** Add `PSVellumPDF.Interop.dll`, a small C# library compiled from a new
   `dependencies/Interop/*.cs` (or a sibling `interop/Interop.csproj` referenced by `build.ps1`). It is
   needed because PowerShell's binder cannot pass `ReadOnlySpan<T>`. That rules out
   `PdfCanvas.SetLineDash`, `SetFillColor(params ReadOnlySpan<double>)`, `SetStrokeColor` and
   `ShowGlyphs*` (check this in pwsh 7.6 while implementing). It also hosts code that must run as
   real .NET types:
   - `CanvasHelpers`: `SetLineDash(canvas, double[], phase)`, `SetFillColor(canvas, double[])`, `SetStrokeColor`, `ShowGlyphs(ushort[])`.
   - `ScriptBlockRenderer : IRenderer`, for Phase 2c. Its `Layout()` returns
     `LayoutResult.Full(area.WithHeight(h))`, or `Nothing()` when `h > area.Height`.
     `Draw(DrawContext)` invokes a `ScriptBlock` with `$canvas` (PdfCanvas), `$box` (the PDF-space
     rect from `ctx.ToPdfRect`) and `$ctx`.
     - It must run on the pipeline thread. It is valid only with the synchronous `Document.Save`
       and `SigningExtensions.Sign`.
     - `SaveAsync` and `SignAsync` run layout under `Task.Run` (`Layout/Document.cs:1310`,
       `Signing/SigningExtensions.cs:120,202`), so the shim throws a clear error when invoked with
       no runspace.
   - `build.ps1 Restore` copies `VellumPdf*.dll` plus `PSVellumPDF.Interop.dll`.
3. **`PSVellumPDF.psm1` loading.**
   - Load in dependency order: `Kernel, Layout, Reader, Signing, Barcodes, Conformance, Fonts.Standard14, PSVellumPDF.Interop`.
   - Before loading, a guard reads each `[AssemblyName]::GetAssemblyName()` and requires version
     `2.0.0.0` and token `b2757187a6d18ae5`. A stale 1.x `lib/` fails with "run ./build.ps1 Restore".
   - Also detect an already-loaded VellumPdf assembly of a different identity in the session.
4. **`build.ps1`.**
   - Copy the VellumPdf `NOTICE` into `lib/` and make `Stage` ship it. It carries the GIF and Adobe Glyph List terms.
   - Add a Pester test proving `[System.Security.Cryptography.Pkcs.SignedCms]` resolves under the
     bundled Pkcs 10.0.6. Don't bundle Pkcs unless that test fails.
   - In CI, bump the PowerShell pin from 7.6.2 to the current 7.6.x (7.6.9 is out).
5. **Fix the module's dependence on 1.x behaviour.** Each fix gets a regression test.
   - **Encoding warnings.** `Private/Write-VellumPdfEncodingWarning.ps1` assumes Latin-1. Under 2.x
     it falsely warns on `• – — … € “ ”`, which now render. Replace it in two parts:
     - **Pre-check**: warn only on characters outside Windows-1252, using
       `[Text.Encoding]::GetEncoding(1252)` with an exception fallback.
     - **Authoritative report**: after save, `Save-VellumPdfDocument` reads
       `$Document.TextEncodingWarnings` (a list of `Rune`) and emits one warning listing the
       distinct code points.
   - **Band truncation.** After save, surface `$Document.BandTruncations` as warnings, e.g.
     "Footer truncated on page 3: dropped 18 chars".
   - **Single-use documents.** A second save throws, and a failed save may leave state that makes a
     retry produce a wrong file (#530). Add a `PSVellumSaved` stamp:
     - `-KeepOpen` keeps the document readable (warnings, inspection) but refuses a second save
       with a clear message from `Assert-VellumPdfDocumentOpen`.
     - After a failed save, stamp the document unusable.
     - Keep the existing temp-file-then-move.
   - **Encryption** (`Protect-VellumPdfDocument`):
     - Refuse an empty `-OwnerPassword` beside a user password up front.
     - Allow `-Conformance PdfUA1` when `Extract` is in the permissions. Today any conformance is
       refused; PDF/A is still refused.
     - Refuse encryption combined with `-UseObjectStreams`, in either order. The engine throws
       `NotSupportedException` at save.
     - Changelog: `/P` bytes differ, and `-EncryptMetadata:$false` now really leaves the XMP in plain text.
   - **Signing.** Use the `PdfSignatureSettings.SubFilter*` constants. Changelog: CAdES signatures
     no longer carry `signing-time`, though `/M` still does.
   - **Tables.** Allow `0` in `-ColumnWidth` to mean auto, since the engine now treats 0, NaN and
     negative widths as auto. Expect geometry changes in tests (double-margin fix, widest-row
     column count).
   - **Eager validation.** Validate values that still slip past the engine, or fail only at save:
     - font size ≤ 0
     - `RowSpan < 1`
     - negative image size
     - zero line width
     - null or empty cell text
     - NaN or ∞ anywhere
     Reuse the rich-cell validation pattern in `Add-VellumPdfTable`.
6. **Latent wrapper bugs** confirmed against the sources. These are breaking fixes, made in 2.0.0.
   - **Heading level is off by one.** `Heading.Level` is zero-based (0 means H1 and a top-level
     outline entry). That is the same in 1.5.4 and 2.3.3 (`Elements/Heading.cs`). The module
     passes 1..6 straight through, so its default heading is tagged **H2**. Fix:
     `$heading.Level = $Level - 1` in `Public/Add-VellumPdfHeading.ps1`.
   - **`-MarginBottom` does nothing** on Paragraph, Heading, List and Table. The bottom edge "adds no
     space before the next element" (`Elements/Paragraph.cs:73`, `ParagraphRenderer.cs:86`). Fix:
     store the space as `PSVellumPendingSpace` on the document and add it to the *next* element's
     top margin in `Private/Set-VellumPdfElementMargin.ps1`. Image, LineSeparator and PieChart honour
     bottom margins natively.
   - **Grandchild list items are silently dropped.** Only one nesting level is rendered
     (`Elements/ListItem.cs:78-93`), but the module accepts depth 64. Fix: cap at one child level
     with a clear error. Warn that the nested unordered marker (U+25E6) shows as `?` with base-14 fonts.
7. Run the existing suite on 2.3.3 and fix the fallout before starting the feature phases.

- **Image** (`Add-VellumPdfImage`):
  - `-MarginLeft/-MarginRight`.
  - `-ReduceToEightBit` (`ImageBitDepth.ReduceToEight`) and `-DecodeToRaster`

  - New `-Format Ccitt -Columns -Rows [-K] [-BlackIs1] [-EncodedByteAlign] [-EndOfLine]`, through `CcittImageLoader.Load(bytes, cols, rows, CcittOptions, ImageLoadOptions)`.

## Phase 2: new Layout features

**2a. `Add-VellumPdfPieChart`**, wrapping `PieChart`, `PieSlice` and `Document.Add(PieChart)`.
- **Input sets.**
  - `-Slice`: hashtables `@{Value; Color; Label}`, or `PieSlice` objects.
  - Pipeline: `-InputObject -ValueProperty -LabelProperty`. It collects in `process` and builds in `end`.
- **Options.**
  - `-Diameter` (> 0, finite; warn when it is wider than the content box, because the engine clamps it).
  - `-StrokeColor -StrokeWidth` (≥ 0).
  - `-Alignment` (Left, Center or Right; Justify is ignored by the engine, so refuse it).
  - `-StartAngle` in degrees, converted to radians (the engine measures from +X).
  - `-CounterClockwise`.
  - `-AltText` or `-Decorative`, mutually exclusive.
  - Margins.
- **Defaults.** Slices without a colour come from a new `Private/Get-VellumPdfPalette.ps1`.
- **Validation.** Check the slices up front: finite, ≥ 0, a positive sum, and at least one slice. The engine otherwise throws at save.
- **`-Legend`.** The engine never draws labels (`Elements/PieChart.cs:40-49`). `-Legend` adds a
  table after the chart (swatch cell with `Background` set to the slice colour, label, percent). It
  reuses `Add-VellumPdfTable` by factoring its core into `Private/New-VellumPdfTableElement.ps1`.

**2b. `Add-VellumPdfBarcode`** (closes #26), through `DocumentBarcodeExtensions.Add(document, barcode)`.
- **Types.** `-Type QrCode|MicroQrCode|DataMatrix|Aztec|Pdf417|Code128|Code39|Ean13|Ean8|UpcA|UpcE|Itf14`.
  EAN and UPC map to `EanBarcode(EanSymbology, digits)`. `-Content`, or `-Bytes` for QR.
- **Common options.**
  - `-ModuleSize` or `-TargetWidth`, in separate parameter sets because the engine throws when both are set.
  - `-Foreground`/`-Background` (`ColorRgb`), `-NoQuietZone`, `-Alignment`, `-AltText`/`-Decorative`, margins.
- **1-D options.** `-BarHeight -ShowText -TextSize -TextFont` (Standard14 only).
- **Per-type options.** Each errors on the wrong type.
  - QR: `-ErrorCorrection`, `-QrVersion`, `-Mask`, `-TextEncoding`, `-Gs1`.
  - DataMatrix: `-Shape`. Aztec: `-AztecFormat`, `-ErrorCorrectionPercent`.
  - PDF417: `-Columns/-Rows/-Compact`.
  - Code 39: `-CheckDigit/-FullAscii`. EAN: `-AddOn`. ITF-14: `-BearerBars`.
- **Early failure.** Call `$barcode.Measure()` in the cmdlet so bad content fails at the call, not at save.
- **PDF/A.** 1-D human-readable text uses a **non-embedded** base-14 font
  (`Barcodes/Barcode1D.cs:22`, `BarcodeRenderer.cs:67` → `PdfDocument.UseFont`). Under any PDF/A
  conformance, default `ShowText` to off, and refuse an explicit `-ShowText`. Point users to
  `-Caption`, which adds a Paragraph in the document's embedded font below the code.
- **Batch codes.** QR Structured Append (`QrCode.StructuredAppend`) and Macro PDF417 (`Pdf417Barcode.MacroSet`)
  are exposed as `-SplitInto <n>` and emit several symbols.

**2c. `Add-VellumPdfDrawing`** (Kernel canvas inside Layout), using the Phase 0 `ScriptBlockRenderer`.
- Usage: `-Height <pt> -ScriptBlock { param($canvas, $box) ... }`.
- A user has the full `PdfCanvas` (gradients, alpha, CMYK fill and stroke, clipping, arcs,
  `ShowTextAligned`), plus `[PSVellumPDF.Interop.CanvasHelpers]` for the span-taking operators.
- `-AltText`/`-Decorative`: the shim wraps the drawing in `BeginMarkedContent("Figure")` with
  `RegisterStructElem`, or in an artifact, when `ctx.Tagged`.
- Text needs `ctx.GetFont()` or `UseEmbeddedFont(handle)`; expose these via `$ctx`.
- Refused with Phase 3's `-ExternalSigner`, because `SignAsync` would run it off-thread.
- Also add `Add-VellumPdfElement -Renderer <IRenderer>` as a thin passthrough for compiled renderers.

**2d. Save-time diagnostics and output**
- `Save-VellumPdfDocument -Stream <Stream>` or `-AsByteArray`, for in-memory output.
- The returned `FileInfo` gets `TextEncodingWarnings` and `BandTruncations` note properties.
- Keep the synchronous save. Document `SaveAsync` as unsupported with scriptblock elements.
- CMYK stays out of the Layout cmdlets, because no Layout property takes `ColorCmyk`. It is
  available in 2c and in Phase 3.

## Phase 3: Kernel page pipeline (forms, links/outlines, drawing/pages, linearize/determinism)

This is a second, explicit pipeline for what Layout cannot reach. It works on
`[VellumPdf.Document.PdfDocument]`; `Layout.Document` is a separate object type.

**Document**
- **`New-VellumPdfPageDocument`** creates the document.
  - Options: `-Conformance`, `-PageSize`, `-Tagged`, `-Language`, `-UseObjectStreams`, `-Linearize`.
  - Determinism: `-DocumentId <byte[16]>` (validated to 16 bytes) and `-Timestamp <DateTimeOffset>`.
  - It shares `Set-VellumPdfDocumentInfo`, `Set-VellumPdfOutputIntent`, `Register-VellumPdfFont`
    and `Protect-VellumPdfDocument` with the Layout pipeline: those take
    `[object]$Document` and dispatch on type.
  - `-Linearize` conflicts:
    - Refuse `-Linearize` combined with `-UseObjectStreams` or encryption up front; the engine
      throws `NotSupportedException` (`Kernel/Document/PdfDocument.cs:577,582`).
    - Warn that signing ignores Linearize (`:171`).

**Pages**
- **`Add-VellumPdfPage`** has `-PageSize`/`-WidthMm/-HeightMm` and `-Rotate 0|90|180|270`.
  - It returns the `PdfPage` and records it on the document.
  - `-PassThru` controls whether the page or the document goes down the pipeline.
  - Pages are addressed by index elsewhere (`-Page 1`).

**Drawing**
- **`Invoke-VellumPdfCanvas -Page <n> -ScriptBlock { param($canvas, $page) }`** creates
  `[PdfCanvas]::new($page)` and calls `Finish()`.
- **Convenience cmdlets on the same canvas:**
  - Shapes and text: `Add-VellumPdfShape` (Rectangle, Line, Ellipse via curves, Arc; fill and
    stroke colour RGB/CMYK, alpha, dash, width), `Add-VellumPdfText` (`ShowTextAligned` at x/y;
    base-14 or embedded font), `Add-VellumPdfGradient` (axial or radial).
  - Placed content: `Add-VellumPdfPageImage` (`RegisterImageXObject` + `DoXObject`) and
    `Add-VellumPdfPageBarcode` (`BarcodeCanvasExtensions.DrawBarcode`).
- **Colour spaces.** `-IccProfile` registers through `RegisterIccBasedColorSpace` + `SetFillColorSpace`.
- **Fonts.** Track font usage via `RegisterEmbeddedFontUsage`.
  - Under PDF/A, base-14 text is embedded automatically through
    `Standard14FontExtensions.EmbedStandard14Font`.
  - Otherwise refuse base-14 text under PDF/A.

**Forms**
- **`Add-VellumPdfFormField -Page -Type Text|CheckBox|Choice|Radio|PushButton -Name -Rect`**, with:
  - `-Value`, `-Checked`, `-Options` and `-Selected` (choice, `-Combo`), `-RadioOption` hashtables
    `@{Page; Rect; ExportValue}`, `-Caption`.
  - `-FontSize` (finite, > 0), `-ReadOnly`, `-Required`, `-Multiline`.
  - Mapping: `AddTextField`, `AddCheckBox`, `AddChoiceField`, `AddRadioButtonGroup`, `AddPushButton`.
- **Validation.**
  - Check text-field values and captions against Latin-1 plus WinAnsi punctuation up front. A
    failure at save throws *after* the document is marked written, which makes it unusable
    (`Forms/AcroFormBuilder.cs:656-681`, `PdfDocument.cs:589`). Field names and values themselves
    may be Unicode (UTF-16 since 1.5.5).
  - Field appearances use non-embedded Helvetica (`PdfDocument.cs:770`). Run
    `Test-VellumPdfConformance` on a PDF/A form sample; if it fails, refuse forms under PDF/A.

**Links and outlines**
- **`Add-VellumPdfLink -Page -Rect (-Uri | -TargetPage [-DestLeft -DestTop]) [-Flags]`**
  - Builds `PdfLinkAnnotation` (with `PdfAnnotationFlags`, default Print) and `RegisterLinkAnnotation`.
  - Reuses the `-LinkUri` scheme allowlist from `New-VellumTextStyle`, factored into `Private/Test-VellumPdfLinkUri.ps1`.
- **`Add-VellumPdfOutlineEntry -Title -TargetPage -Level [-Collapsed]`** maps to `PdfOutlineEntry.IsExpanded`.

**Save and sign**
- `Save-VellumPdfDocument` dispatches on type. It keeps the same atomic temp-file write, signing
  path (`SigningExtensions.Sign(PdfDocument,…)`) and warnings (`PdfCanvas.TextEncodingWarnings`, collected per canvas).

**Implementation notes**
- Building `required`/`init` objects (`PdfLinkAnnotation`, `PdfOutlineEntry`) from PowerShell
  works by property assignment after `new()`, as the module already does for `Heading.Level`.
  Prove it in tests first. If it doesn't work, add factory helpers to the Interop shim.

## Phase 4: Signing (`Set-VellumPdfSignature`, both pipelines)

- **Levels.** `-Level B-B|B-T|B-LT|B-LTA` maps to `PadesLevel`. B-LT and B-LTA require `-TimestampUrl`.
- **Revocation.** `-RevocationClient`, defaulting to `HttpRevocationClient(HttpClient, -RevocationTimeout)`.
  Reuse the no-redirect `SocketsHttpHandler` and dispose it on save, as `PSVellumTimestampHttpClient` is today.
- **Placement and encoding.**
  - `-SignaturePage` (0-based in the engine; the cmdlet takes 1-based and checks the page count at save).
  - `-SubFilter Pades|Pkcs7`.
  - `-EstimatedSignatureSize`, with a hint when the LTV placeholder is too small.
- **External keys.**
  - `-ExternalPrivateKey <AsymmetricAlgorithm>` keeps the synchronous `Sign` path (HSM or PKCS#11 keys).
  - `-ExternalSigner <IExternalSigner>` forces `SignAsync(...).GetAwaiter().GetResult()`. Document
    that the signer must be a compiled type, because `SignAsync` runs off the pipeline thread.
    Refuse it when the document holds `Add-VellumPdfDrawing` elements.
- **Errors.** Wrap the engine's up-front refusal of a non-minimally-encoded certificate serial with a hint.

## Phase 5: Conformance (`Test-VellumPdfConformance`, closes #25)

- **Input.** `-Path/-LiteralPath`, bound by property name so it accepts the `FileInfo` from Save, or `-Bytes`.
- **Profile.** `-Profile PdfA2b|PdfA2u|PdfA2a|PdfUA1`. When omitted, use
  `PdfPreflight.DetectClaimedProfiles` and validate each claimed profile.
- **Passwords.** `-Password` (SecureString) maps to the `string? password` overloads. Catch
  `PdfPasswordException`, which is not a `NotSupportedException`.
- **Output.** `PSVellumPDF.PreflightResult` objects (Profile, IsCompliant, Errors/Warnings counts,
  and Assertions with RuleId, Clause, Severity, Message, ObjectRef), plus `PSVellumPDF.Format.ps1xml`.
  `-Quiet` returns `[bool]`.
- **`Save-VellumPdfDocument -Validate`** preflights the temp file before the atomic move and fails
  when the document isn't compliant.

## Phase 6: Reader (Preview, marked experimental in help)

All Reader access goes through `Private/Open-VellumPdfReader.ps1`, which builds
`PdfReader.Open(bytes, [PdfReaderOptions]@{Password; AllowReconstruction})` and disposes in
`finally`. Reader is Preview: `Open(bytes, string)` was removed in 2.3.0.
- **`Get-VellumPdfInfo`** returns:
  - `PageCount`, and the pages (Index, MediaBox, CropBox, Rotate).
  - `Encryption`: V, R, ciphers, KeyLengthBits, Permissions, IsOwnerAccess.
  - `Signatures`: **only** SubFilter, SigningTime and ByteRange/Contents length; the reader exposes
    no signer name or reason.
  - `WasReconstructed` and `Diagnostics`.
  - Claimed conformance, via `PdfPreflight.DetectClaimedProfiles`.
- **`Get-VellumPdfText [-Page]`** uses `ExtractText(PdfTextExtractionOptions{Pages; PageSeparator})`.
  Document its limits: simple fonts only, no inserted spaces.
- **`Export-VellumPdfImage -Destination`** uses `ExtractImages()`. It writes PNG through
  `TryEncodePng`/`TryEncodePngWithAlpha` when `CanEncodePng`, and otherwise the raw data with `FileExtension`.
- **`Unprotect-VellumPdfDocument -Password -Destination`** uses `SaveDecrypted`. It supports
  ShouldProcess and needs `-AllowInvalidatingSignatures` for signed input.
- Update the manifest `Description`: the module still cannot edit, split or merge PDFs.
