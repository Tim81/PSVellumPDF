# Review findings and remaining VellumPdf 2.3.3 gaps — plan

Status: **implemented** (see the status notes at the end). Branch `claude/pensive-ptolemy-e0t6fy`, module 2.0.0 (unreleased).

## Sources

- **R1** functional-correctness review (9 findings).
- **R2** PowerShell-correctness review (11 findings).
- **R3** adversarial-input, conformance and test-adequacy review (12 findings + test gaps).
- **G** API gap research: reflection over all 7 VellumPdf 2.3.3 assemblies (162 types, ~1,100
  members) matched against the module source, then confirmed against the package XML docs.

Every review finding was reproduced by its reviewer. The four High items were reproduced again
before this plan was written: the parser hang, `-ErrorAction SilentlyContinue` suppressing
validation, `-LineCap round` writing `-1 J`, and Code128 in PDF/UA failing preflight.
Duplicates across reviewers are merged and cite every source.

## Decisions needed before starting

1. **Release shape.** Option A: everything ships in 2.0.0 (it is unreleased). Option B (recommended):
   phases 1–4 complete 2.0.0, phases 5–7 become 2.1.0.
2. **Default font propagation (P3-2)** changes output for existing scripts: lists, tables, bands and
   text runs follow `-DefaultFont`/`-DefaultFontSize`, and drop from 12 pt to the 11 pt default.
   Recommended: do it in 2.0.0, as a documented breaking change.
3. **Coordinate limit (P1-5).** Recommended: ±14,400 pt, the 200-inch maximum page size. That is
   well inside the PDF number limits PDF/A enforces and rejects obvious mistakes.
4. **`-WordSpacing` with embedded fonts (P3-1).** Recommended: position the words individually,
   as the justified text box does, rather than refusing the option.

## Phase 1 — Error model and input robustness (cross-cutting, do first)

- **P1-1 Terminating errors** [R2-1, High].
  - **Defect:** every `throw` in a public cmdlet is suppressed by `-ErrorAction SilentlyContinue/Ignore`,
    and execution continues: validation is skipped, conflicting colours are both written, and the
    path parser loops for ever.
  - **Fix:** wrap each public `process`/`end` body in `try { … } catch { $PSCmdlet.ThrowTerminatingError($_) }`
    via a small shared pattern. Private helpers keep `throw`.
  - **Tests:** one table-driven test runs every public cmdlet with invalid input and
    `-ErrorAction SilentlyContinue`, and asserts it still terminates.
- **P1-2 Parser stall** [R2-1, High]. In `Private/ConvertTo-VellumPdfPathOps.ps1`, fail hard on an
  unknown command independently of P1-1, so `$i` always advances. Test with `timeout`.
- **P1-3 Case-insensitive enum mapping** [R2-2, High]. `Add-VellumPdfPath.ps1:199-200` and
  `Add-VellumPdfShape.ps1:233-234` use `IndexOf` on a ValidateSet value, so lower case gives -1.
  Replace with a hashtable lookup. Grep for other `.IndexOf($` uses on ValidateSet values.
  Test `-LineCap round -LineJoin bevel` → `1 J`/`2 j`.
- **P1-4 Strict-mode-safe property access** [R2-3].
  - **Where:** `Add-VellumPdfTable.ps1:237`, `Add-VellumPdfPieChart.ps1:156,237-238`.
  - **Fix:** read properties with `PSObject.Properties[$name]`.
  - **Tests:** records with missing properties; a pscustomobject slice without Color.
- **P1-5 Coordinate and size bounds** [R3-1, Medium-high].
  - **Fix:** a shared helper `Assert-VellumPdfCoordinate` (finite and within the agreed limit, see
    decision 3). Use it in the path parser, points, text, text box, shape, gradient, clip, page
    image and page barcode. The error names the cmdlet and the parameter.
  - **Tests:** `1e300`, `3e9`, `1e40` are refused; a file at the limit passes `qpdf --check`.
- **P1-6 Input helper** [R2-8, R3-7].
  - **Fix:** in `Private/Get-VellumPdfInput.ps1`, use `ContainsKey('Bytes')` instead of a truthiness
    test. A missing file gives "<Cmdlet>: file not found: …"; a 0-byte file or array gives "not a PDF".
- **P1-7 Wildcard characters in piped file names** [R2-4].
  - **Defect:** a piped FileInfo binds to `-Path` (alias `FullName`) and is treated as a wildcard.
  - **Fix:** remove the `FullName` alias and by-property binding from `-Path`, and give
    `-LiteralPath` the `PSPath` alias by property name.
  - **Applies to:** Get-VellumPdfText/Info, Test-VellumPdfConformance, Export-VellumPdfImage,
    Unprotect-VellumPdfDocument.
  - **Test:** `report[1].pdf` piped through `Get-Item` and `Get-ChildItem`.

## Phase 2 — Conformance correctness

- **P2-1 One predicate for conformance needs** [R1-3, R1-9].
  - **Fix:** a helper `Get-VellumPdfConformanceNeeds` returns `IsPdfA`, `NeedsEmbeddedFonts`
    (PdfA2* or PdfUA1) and `Tagged`. Use it:
    - for barcode human-readable text (`Add-VellumPdfBarcode.ps1:270`, `Add-VellumPdfPageBarcode.ps1:161`),
      which currently stays on in PDF/UA and fails 7.21.4.1;
    - for the CMYK output-intent warning (`Add-VellumPdfShape.ps1:191`, `Add-VellumPdfPath.ps1:159`),
      which is wrongly raised for PDF/UA-only documents.
  - **Tests:** PdfUA1 with Code128 passes `-Validate`; no CMYK warning in PdfUA1.
- **P2-2 Missing-glyph warnings** [R3-2, Medium-high].
  - **Defect:** characters the embedded font (or the auto-embedded Liberation substitute) has no glyph
    for become `.notdef` with no warning. Without `-Validate`, the file claims PDF/A and fails 6.2.11.8.
  - **Fix:** check each rune with `EmbeddedFontHandle.GetGlyphId`; glyph 0 means missing. Warn, naming
    the character and the cmdlet, in Add-VellumPdfText, -TextBox, Set-VellumPdfPageBand and the
    flow-document text cmdlets that take `-FontHandle`.
- **P2-3 Language tags** [R3-3]. Validate BCP 47 syntax for every `-Language` (document, text, text box,
  paragraph, heading, cell) in one helper. The preflight does not check structure-element `/Lang`.
- **P2-4 Empty accessibility content** [R3-4].
  - Reject whitespace-only `-AltText` everywhere.
  - In a tagged document, a text box with no words throws for heading roles and draws nothing for
    other roles.
  - Close the gap that lets `Add-VellumPdfPageImage` take whitespace alt text.
- **P2-5 Output intent component count** [R1-5]. `Set-VellumPdfOutputIntent.ps1:110` derives the count
  with `Get-VellumPdfIccComponentCount` and refuses a mismatch; `-ComponentCount` becomes optional.
- **P2-6 `-Validate` message** [R3-11] names New-VellumPdfPageDocument as well (`Save-VellumPdfDocument.ps1:136`).

## Phase 3 — Functional fixes

- **P3-1 `-WordSpacing` with embedded fonts** [R1-1].
  - **Defect:** `Tw` does nothing for 2-byte glyph codes, so the text is placed short; right-aligned
    text ends 150 pt early in the repro.
  - **Fix:** for embedded fonts, place the words individually (each with its trailing space glyph, as
    the text box does) and compute alignment from that.
  - **Test:** render and measure the ink, as the reviewer did, and check the glyph runs.
- **P3-2 Document default font propagation** [R1-2] (behaviour change, decision 2).
  - **Fix:** build the list base style, table `DefaultCellStyle`, band style and `New-VellumPdfTextRun`
    style from `Resolve-VellumPdfDefault`. Paragraph `-Run` fills in a missing font and size.
  - **Tests:** a `-DefaultFont Courier -DefaultFontSize 14` document has Courier 14 in every element.
- **P3-3 Table column index with spans** [R1-4]. `Add-VellumPdfTable.ps1:395,423`: advance the column
  index by ColSpan and track RowSpan occupancy, for `-ColumnAlignment` and the `-ColumnWidth` count check.
- **P3-4 Text box** [R1-6, R1-7, R3-5, R3-6].
  - Split on `[ \t]+` only, so no-break and other Unicode spaces keep their meaning and their character.
  - Use `Floor(MaxHeight / Leading + 1e-9)` with no minimum of 1; zero lines warns.
  - Warn whenever the height used is greater than `-MaxHeight`.
- **P3-5 Clip `-Page`** [R3-8]. Inside the block, default `-Page` for the module's page cmdlets to the
  clip's page with a scoped `$PSDefaultParameterValues`, restored afterwards. Warn when the block drew
  nothing on the clipped page.
- **P3-6 Page band overflow** [R3-9]. Measure the resolved text; warn (once per band) when it is wider
  than the page minus `-Inset`, and record it like flow documents' `BandTruncations`.
- **P3-7 Invoke-VellumPdfCanvas state balance** [R3-10]. Record the save-state depth around the block.
  Wrap the block in an outer `q … Q`, and fail with a clear message if the block's own `q`/`Q` are
  unbalanced, so the help's "graphics state is restored" holds.
- **P3-8 Pie chart `-InputObject` array** [R2-7]. `Add-VellumPdfPieChart.ps1:226` enumerates the array.
- **P3-9 `OutputType`** [R2-9]. Save-VellumPdfDocument declares both document types for `-PassThru`.
- **P3-10 Help examples and culture** [R1-8, R2-5, R2-6, R2-10].
  - Fix the ring example (`-f` precedence) and the clip example (`-Direction LeftToRight`).
  - Make `examples/10` culture-neutral (`[string]::Format([cultureinfo]::InvariantCulture, …)`) and
    state in the `-Data` help that numbers use a dot.
  - Fix the Register-VellumPdfFont example's relative `ReadAllBytes`.
  - Add a test that extracts every `.EXAMPLE` code block and runs the self-contained ones.
- **P3-11 ValidateRange types** [R3-12]. Use double bounds (`0.0, 1.0`) on double parameters so NaN gets
  a meaningful message, or an explicit `IsFinite` check.

## Phase 4 — Export-VellumPdfImage codec output [G3]

- **Defect:** the help (`Public/Export-VellumPdfImage.ps1:10-13`) says JBIG2/CCITT are written "as
  their original codestream (.jb2, .tif) … use those files directly". This is false:
  - The engine documents `.jb2` as the embedded organisation: no file header, no end-of-page or
    end-of-file segments, and the `/JBIG2Globals` arrive separately and are dropped.
  - CCITT is written as `.ccitt` raw data without its `/DecodeParms`.
  - Raw samples that cannot become PNG are written as headerless `.bin`.
- **Fix:**
  - **CCITT:** wrap the data in a minimal single-strip TIFF (Compression 3 or 4 from K, PhotometricInterpretation
    from BlackIs1, width and height, and the T4/T6 options from EncodedByteAlign and EndOfLine). The
    result opens in any viewer.
  - **JBIG2:** write a standalone JBIG2 file: file header, the globals segments, the page segments,
    end-of-page and end-of-file. The engine docs note the page association is already 1. If that proves
    unreliable, write the `.jb2` and a `.jb2globals` side file and say exactly that in help.
  - **Raw `.bin`:** skip with a warning naming the colour space, or write a `.raw` plus a JSON
    descriptor (width, height, bits per component, colour space).
- **Output:** each written file object gains note properties: Encoding, ColorSpace (family, component
  count), BitsPerComponent, IsInline, HasSoftMask/IsStencilMask. This also covers the small reader gap.
- **Tests:** JBIG2 and CCITT fixtures (`tests/assets/sample.jb2` exists; add a CCITT G4 source) are
  embedded, exported, and decoded by an independent decoder where available (e.g. ImageMagick or
  libtiff tools; otherwise structural checks).

## Phase 5 — Tagged structure for page documents [G1]

- **Gap:** `PdfStructElem.AddChild`/`Children`, `TableHeaderScope`, `TableRowSpan`/`TableColSpan` are
  unused. Every page-document tag is registered flat (`Private/Invoke-VellumPdfTagged.ps1:42-47`).
  Page documents have no table at all.
- **Spike first:** confirm that the engine writes the tree, the ParentTree and the MCIDs correctly for
  nested elements registered once at the root (children carry Page and Mcid). Check with the preflight
  and with R3's `check.py`.
- **P5-1 `Invoke-VellumPdfTagged`** gains an optional parent element: when one is given, the new element
  is added with `AddChild` instead of `RegisterStructElem`.
- **P5-2 `Use-VellumPdfStructure -Type Sect|Div|Art|Part -ScriptBlock {…}`**: groups everything tagged
  inside the block under one element. Implement as a scoped "current parent" on the document, so
  existing cmdlets nest without new parameters. Nesting allowed.
- **P5-3 `Add-VellumPdfPageTable`:**
  - Draws a grid at x/y: rows from objects or arrays, `-Header`, column widths, padding, borders,
    backgrounds, ColSpan/RowSpan, wrapping cell text (reusing the text box line breaker), and alignment.
  - Tagged as Table / TR / TH (`Scope` Column, or Row for `-RowHeader`) / TD with span attributes.
    Borders and backgrounds are artifacts.
  - Returns its height with `-PassThru`. A table taller than the space is an error in this version
    (no page flow).
- **P5-4 `Add-VellumPdfPageList`:** bullet or numbered items with wrapped bodies. Tagged
  L / LI / Lbl / LBody; one nesting level, as in flow documents.
- **Tests:** structure-tree assertions (types, nesting, `/A /O /Table /Scope`, spans); PDF/UA-1 and
  PDF/A-2a `-Validate`; the CI veraPDF informational step gets a sample.

## Phase 6 — Transforms and rotation [G2]

- **P6-1 `Use-VellumPdfTransform -Rotate <deg> [-OriginX -OriginY] [-Scale] [-TranslateX/-Y] -ScriptBlock`.**
  Like the clip scope (`q`, `cm`, then the block, then `Q`), with the same `-Page` defaulting as P3-5.
  It covers text, text boxes, shapes, paths, images and barcodes at once.
- **P6-2 `-Rotation` convenience** on Add-VellumPdfText (rotation about the anchor point, using
  `SetTextMatrix` so alignment still holds) and on Add-VellumPdfPageImage (rotation about its centre).
- **Tests:** content-stream matrices; render checks for 90° and 45° text and image placement; tagging
  is unaffected.

## Phase 7 — Measurement and small gaps [G4 + small]

- **P7-1 `Measure-VellumPdfText -Text -FontSize (-Font | -FontHandle) [-CharSpacing -WordSpacing -HorizontalScale]`.**
  Returns Width, Ascent/Descent if the engine exposes them (else size-based), and the missing glyphs.
  It shares one implementation with Add-VellumPdfText alignment and the text box.
- **P7-2 Get-VellumPdfInfo signatures** also return the signature bytes (`Contents`) so scripts can
  verify them with SignedCms. The help shows how.
- **P7-3 Gray colour:** `-FillGray`/`-StrokeGray` on Shape and Path (DeviceGray `g`/`G`), for print
  workflows.
- **P7-4 Built-in profiles:** `Set-VellumPdfOutputIntent -Builtin Srgb|GenericCmyk` uses
  `VellumPdf.Document.IccProfiles`, so no file is needed.

## Out of scope (with reasons)

- **Link and form-field tagging:** blocked by the engine (Tim81/VellumPDF#569, #550).
- **Deferred signing:** `PdfDocument.PrepareForSigning` exists, but there is no public API to complete
  a prepared signature.
- **Low-level classes:** Core PDF objects, IO writer/xref, Layout renderer classes and font-embedder
  internals are engine plumbing.
- **Async overloads:** they add nothing to a synchronous cmdlet.
- **Layout `ColorCmyk`:** no Layout element accepts it, per the engine's own docs.

## Order of work and verification

Phases 1 → 2 → 3 → 4 → 8 for 2.0.0; then 5 → 6 → 7 (2.1.0 under option B). Each phase:

- tests for each item, failing first where the defect is reproducible;
- the full suite;
- lint approximation locally and `./build.ps1 Lint` in CI;
- qpdf and preflight on the samples;
- one commit per phase, authored without AI attribution, pushed to the branch.

## Status notes (implementation)

Decisions taken: everything ships in 2.0.0; default font propagation is a documented breaking change; coordinates are
limited to +-14,400 pt; `-WordSpacing` with an embedded font places the words individually.

Implemented in this order, one commit per phase, each with tests: (1) terminating errors, bounded coordinates, input
helpers; (2) conformance checks (barcode captions in PDF/UA, missing glyphs, language tags, alt text, ICC component
count); (3) functional fixes (word spacing, default font, table spans, text box limits, scopes, band overflow, canvas
balance, help examples run under en-US and de-DE); (4) CCITT-as-TIFF and standalone JBIG2 export; (5) nested structure,
`Add-VellumPdfPageTable`, `Add-VellumPdfPageList`, `Use-VellumPdfStructure`; (6)-(7) `Use-VellumPdfTransform`,
`-Rotation`, `Measure-VellumPdfText`, grey colours, signature bytes; (8) test fixes, singular helper names, docs.

Where the work differed from the plan above:

- **Nested tags**: no spike was needed; the engine source confirms a leaf has an MCID and a group has children, never both.
- **Text rotation** uses `cm` about the anchor, because `ShowTextAligned` writes an absolute `Tm`.
- **Canvas balance** is detected at save time by scanning `PdfPage.ContentBytes` (new C# helper `ContentStreamBalance`).
- **JBIG2**: VellumPdf's loader reads only the 8-byte ID string, so the standard file (flags + page count) the export
  writes cannot be embedded again; the export is checked structurally. CCITT is verified pixel for pixel against poppler.
  An upstream issue for the loader has not been filed.
- **`Set-VellumPdfOutputIntent -Builtin`** (P7-4) was dropped: `-Cmyk` already uses the built-in CMYK profile and the default
  PDF/A intent is already the built-in sRGB one.
- **`Get-VellumPdfInfo`** returns signature bytes with `-IncludeSignatureContents` instead of always.
- **Lint**: `-Profile` is kept; PSScriptAnalyzer could not run locally, so the CI Lint job decides.
- Still open: `docs/PSVellumPDF/*.md` needs `./build.ps1 Docs`; veraPDF and the new rendering-based CI steps have not run.
